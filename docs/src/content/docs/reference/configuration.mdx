autoducks is configured via `.autoducks/autoducks.json` at the root of your repository.

## Full schema

```json
{
  "command": "/quack",
  "providers": {
    "its": "github",
    "git": "github",
    "llm": "claude"
  },
  "defaults": {
    "model": "claude-sonnet-5",
    "effort": "high",
    "max_turns": 50,
    "base_branch": "main",
    "integration_branch": "main",
    "merge_method": "auto"
  },
  "triggers": {
    "architect": [],
    "engineer":  [],
    "execute":   [],
    "fix":       [],
    "revert":    [],
    "close":     []
  },
  "security": {
    "trusted_associations": ["OWNER", "MEMBER", "COLLABORATOR"],
    "allow": [],
    "deny": [],
    "codeowners": false,
    "per_agent": {
      "revert": { "trusted_associations": ["OWNER", "MEMBER"] },
      "close":  { "trusted_associations": ["OWNER", "MEMBER"] }
    }
  }
}
```

<Aside type="note">
`integration_branch` and `max_turns` are optional — omit them unless you need the fork workflow or a turn cap at the global tier.
</Aside>

## `command`

The slash-command prefix. Must match `^/[a-z0-9-]+$`; anything else falls back to the default.

**Default:** `/quack`

GitHub Actions evaluates workflow `if:` guards without reading repository files, so the prefix is **baked into the workflow YAML**. After changing it, regenerate and commit the guards:

```bash
bash scripts/update-triggers.sh
```

## `providers`

Selects the implementation for each provider interface.

| Key | Value | Status | Description |
|-----|-------|--------|-------------|
| `its` | `github` | ✅ Supported | GitHub Issues via the `gh` CLI |
| `git` | `github` | ✅ Supported | Git CLI with GitHub repository operations |
| `llm` | `claude` | ✅ Supported | Anthropic Claude via the Claude Code action |

## `defaults`

Default runtime parameters for all agents, unless overridden by a [directive argument](/reference/slash-commands#overrides) or a per-agent `defaults.json`.

### `defaults.model`

The Claude model ID for LLM agents. **Default:** `claude-sonnet-5`

| Model | Use case |
|-------|----------|
| `claude-sonnet-5` | Default — good balance of speed and quality |
| `claude-opus-4-8` | Best quality for design/planning work |
| `claude-haiku-4-5` | Fastest, lowest cost — simple execution tasks |

### `defaults.effort`

LLM effort level: `off`, `low`, `medium`, `high`, `max`. **Default:** `high`

("effort" follows the cross-provider convention — OpenAI `reasoning_effort`, Anthropic `output_config.effort`.)

### `defaults.max_turns`

Maximum agentic turns per run. Optional at every tier; when unset everywhere, the Claude provider action falls back to `50`.

### `defaults.base_branch`

The **cut-point**: the branch that pipeline branches are created from. **Default:** `main`

When `integration_branch` is unset, `base_branch` also serves as the PR target.

### `defaults.integration_branch`

The **PR target**: where the final pipeline PR is opened. **Default:** unset (falls back to `base_branch`).

Exists for **fork workflows**: cut from the upstream `base_branch`, land PRs on a fork-local branch. The invariant `merge-base(pipeline-branch, integration_branch) == base_branch` always holds.

### `defaults.merge_method`

Method for auto-merging task/fix PRs into the pipeline branch. **Default:** `auto`

| Value | Description |
|-------|-------------|
| `auto` | Probe the repository's allowed methods, preferring `merge` → `squash` → `rebase` |
| `merge` / `squash` / `rebase` | Force one method |

`auto` keeps autoducks working on squash-only or rebase-only repos without configuration.

## `triggers` — custom trigger aliases

Per-team alias verbs, keyed by agent (`architect`, `engineer`, `execute`, `fix`, `revert`, `close`):

```json
{
  "triggers": {
    "engineer": ["blueprint"],
    "execute":  ["ship"]
  }
}
```

Rules: lowercase `[a-z0-9-]+`, no collision with built-in verbs/aliases, unique across agents. Aliases resolve to the canonical verb everywhere — routing, `#auto:` chains, and cascade included.

Like the prefix, aliases must be **baked into the workflow guards**:

```bash
bash scripts/update-triggers.sh
```

The script validates the whole block first (a bad alias is a hard error, never baked), regenerates each guard wholesale (idempotent — byte-identical when nothing changed), and mirrors `.github/workflows/` ↔ `.autoducks/runtimes/github-actions/`.

## Per-agent defaults

Each agent can have its own `.autoducks/agents/<agent>/defaults.json`:

```json
{
  "model": "claude-opus-4-8",
  "effort": "high"
}
```

Agent directories: `architect`, `engineer`, `maestro`, `developer`, `fix`, `revert`, `close`.

**Priority (highest to lowest):**
1. Directive argument in the comment (`model:`, `effort:`, `turns:`)
2. Agent-level `defaults.json`
3. Global `.autoducks/autoducks.json`
4. Provider action default — applies only to `max_turns` (`50`)

## `security`

Every trigger passes the [Authorization Gate](/reference/security) before any agent runs — before any reaction or status comment. The `security` block controls trusted author associations, allow/deny lists, per-agent overrides (keys: `architect`, `engineer`, `execute`, `fix`, `revert`, `close` — the Maestro and Developer share the `execute` policy), and optional CODEOWNERS integration.

See the [Security reference](/reference/security) for the full threat model and schema.
